# 审计证据说明

这些文件用于 2026-11-02 的角色流程机制审计，不是新的业务验收结果。

- `ledger.json`：2026-10-31 00:00 至 2026-11-02 11:56:21（UTC+08:00）的主要统计。采集时系统持续运行，各查询不是同一长事务。`current_*` 是当时状态，不代表此后的实时状态。
- `telemetry.json`：沿用上述时间窗。执行与选定业务转换的时间关联不等于有效率或因果关系。计时库与物理请求库覆盖不同，禁止相加。日志提及数不等于去重故障数，不同日志也不能累加。
- `current-state-supplement.json`：12:50:33 的单次只读事务补查。仅用于纠正现场状态，不更新旧统计分母。
- `review-state.json`：12:48 补查的原生服务快照，七批均完整结束。服务文件保留等待裁决状态，随后账本已有裁决，应按层次和时间区分。
- `deployment.json`：12:48 的激活清单哈希核验。证明所列文件匹配，不证明所有在途帧或全部进程均已采用新代码。
- `versions.json`：角色池登记版本与磁盘技能版本的对比。版本行通过文本筛选采集，辅助行可能含说明，首条版本字段为比较依据；不包含身份凭据。
- `capacity.json`：一次有预算上限的容量观察。`complete=false` 的零值表示未完整扫描，不能当无占用；总量为下界。
- `log-error-classification.json`：54 处数据库操作错误的类别提及统计。其中 `last_stack_file` 使用邻近缓存，**不能用于调用栈归因**。
- `sql-errors.json`：字段/表错误的提及统计；其中 `frames` 同样只是附近日志，可能混入前一个异常，**不能据此认定运行时源文件写错 SQL**。
- `sql-error-context-check.json`：纠偏后的同条目检查，51 处字段/表错误提及中 44 处异常前最后一段栈含 `<string>`。支持临时脚本来源线索，仍不作为去重事故数或对其余错误的排除证明。
- `code-snapshot.json`：源码路径、定位行、哈希及本次发现索引；对照的是含前轮未提交修改的实际工作区。
- `database-storage-check.json`：13:35起新增的只读容量专项核查，包含表页占用、结果正文分组、日分布和快速结构检查。各查询独立采集，不代表附件总量；快速检查通过不等于业务内容或引用已全量核验。
- `database-payload-samples.json`：三条按表扫描先匹配的大正文样本，只保存字段大小、哈希及跨样本重复事件统计。不是随机样本，不能直接外推全库去重率或压缩率。
- `validation.json` 对应最初整体报告版本；容量专项补充后的文档校验另见 `database-storage-validation.json`，保留原校验回执不覆盖。
- `token-usage-current.json`：13:55截止的角色物理请求用量，含完整日期、前后窗口、角色/用途/路线、首请求和后续请求分组。缓存为输入子集，未知用量不补零；前后工作不同，不能作为因果节省率。
- `token-context-samples.json`：每个角色最近八份业务启动上下文的大小与字段分布，只保存元数据；非随机样本，字节减幅不能替代token减幅。投影元数据的大小口径未计其自身新增字段。
- `token-review-usage.json`：219份现有诊断定位到209个独立审查会话，按会话路径和响应身份去重。只汇总响应时间窗口内已报告用量，未保证所有审查覆盖，不能与角色统计直接拼成全系统总量。
- `token-findings-summary.json`：上述用量、上下文数据的派生比例和比较结果；保留任务及时间窗不同的限制。
- `collect_token_usage.py`、`collect_token_context_and_reviews.py` 为本次新增只读采集程序。重跑会改变或覆盖采集时点；查看冻结结果时不要先重跑。
- `collect_ledger.py`、`collect_telemetry.py` 是只读采集程序。运行它们会覆盖相应 JSON 并改变统计时点，复核原结论时应读取冻结文件，不要先重跑。

采集程序未读取或保存角色身份令牌、环境密钥和原始会话正文。账本中少量自由文本检查点仍随结构化查询保留；它们是历史陈述，不是本轮事实或授权证明。

本次新增建议没有部署，没有改任务、批准、合入或验收状态，没有重启业务栈或发送群消息。此前修复记录里的部署和测试，只证明各自说明的范围。
