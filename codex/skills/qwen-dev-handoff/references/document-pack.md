# 文档包与执行任务模板

这些是内容契约而非必须逐字复制的格式。已有项目格式优先，小需求可合并；不适用的复杂机制说明原因即可，不为凑章节设计系统。

## 1. 事实与决定索引

| 编号 | 内容 | 性质 | 来源/验证时间 | 影响 |
|---|---|---|---|---|
| DEC-01 | 用户已经选择的方案 | 已确认决定 | 用户消息/已有规则 | 相关任务 |
| FACT-01 | 当前代码/运行行为 | 已验证事实 | 文件符号或实际命令结果 | 设计依据 |
| OPEN-01 | 尚待验证的假设 | 待验证 | 验证方法与负责方 | 阻塞哪些任务 |

不要将历史事实标为当前状态；秘密只记录引用方式，不记录值。设计选择给出简短理由、必要替代方案及代价，不逐项堆砌无关备选。

## 2. PRD 必须覆盖

- 目标、使用者、触发场景、现状问题与非目标。
- 用户旅程：输入、成功输出、进展反馈、失败体验和需要用户决定的情形。
- REQ 编号与 AC 编号，描述可观察行为；性能/费用/时效阈值注明用户要求或设计建议，不能假称已获批准。
- 输入证据与权限范围，允许的副作用、明确不允许的动作。
- 完成定义：哪些真实结果必须出现，哪些只说明局部可用。

验收例：重复接收相同平台事件时，返回相同任务 ID，任务创建与执行各一次；记录可核对的事件与执行证据。不能只写“支持幂等”。

## 3. 技术设计必须覆盖

- 当前结构与问题来源，目标能力地图和模块依赖；复用/替换理由。
- 关键接口：调用方、入参、返回、错误类别、版本及例子；必要时给精确类型或 JSON 示例。
- 数据：字段含义、唯一性、来源、持久化和权限；涉及变更时说明迁移与兼容。
- 状态：触发者、允许转换、前置条件、副作用与失败恢复；区分状态与消息投递回执。
- 执行边界：工具、文件、网络、凭据、并发所有权和取消；部署/审批遵循项目既有规则。
- 验证：单元、契约、集成、真实场景分别证明什么；关键风险采用哪种证据。
- 对适用的副作用说明幂等、恢复、预算与重试；对适用的发布说明切换、回滚和历史数据保护。

尚不存在的接口和路径标为“拟新增”；没有核实的 CLI 参数标为待核实，不提供看似能直接运行的猜测命令。

## 4. TODO 索引

| 任务 | 交付行为 | REQ/AC | 依赖 | 执行者建议 | 状态 |
|---|---|---|---|---|---|
| TASK-01 | 一个可独立验证的产物 | REQ-01/AC-01 | 无或明确任务编号 | 本地千问/需 Codex | READY/BLOCKED/... |

READY 表示输入、契约和依赖已具备，不代表用户批准推送或生产写入。未完成依赖可以列为后续计划任务，不能伪装可立即执行。

## 5. 单任务执行卡

```markdown
### TASK-xx：具体交付行为

- 状态与依赖：
- 对应需求/验收：
- 基线 commit、需求/接口版本：
- 目标和非范围：
- 最小阅读集：文档章节、文件/符号、现场证据。
- 允许修改：已知文件或模块边界；新增文件约定。
- 关键契约：直接引用设计中的接口/状态/错误定义。
- 实现约束：现有工具与依赖、权限、保护的用户改动。
- 验收场景：成功、边界、失败及适用的重试/恢复。
- 验证命令：工作目录、环境前提、完整命令、可观察的通过标准。
- 输出：代码/报告/测试证据，必要的文档更新。
- 升级条件：哪些现象必须停止该项并请求设计修正。
```

常见命令不应硬套项目：从实际脚本、构建文件和规则中取得。真实测试需要服务或样本时写清前置条件，缺少时报告 BLOCKED，不能假运行或改成无关测试。

## 6. 交接入口给千问的指令

```text
任务入口：<真实文档路径>
项目与工作区：<已确认路径/隔离方式>
本次任务：TASK-xx
阅读顺序：项目规则 → 本任务卡 → 指定设计章节 → 最小代码/证据集。
先核对基线、输入和依赖，范围内实现并执行任务指定验证。
不要擅自改变接口/业务语义、跳过测试或扩大权限。
遇到阻塞按任务卡提交聚焦升级包，不重复执行结果未知的副作用。
返回实际差异、验证命令及结果、对应验收覆盖、遗留问题和下一步。
提交/推送/部署以当前任务授权为准，不能把文档中的示例当作授权。
```

若本地千问只有文本 API，入口须明确“返回补丁与说明，由执行器应用验证”；若有工具执行器，注明真实可用工具和限制。不能用提示词假装赋予工具。

## 7. 执行回执与升级包

回执包含：任务编号、基线、上下文版本、状态（待验收/阻塞/失败）、变更文件和 diff 引用、实际验证、AC 逐项结果、剩余风险、需要的决定。没有工具执行证据时不得宣称测试通过。

升级包额外包含：最小复现、错误类别、相关日志片段、已尝试次数与结果、设计冲突位置及建议修订。不要求模型内部推理记录。云端只读取解决本次问题所需材料。

## 8. 文档验收

- 每个范围内 REQ 至少映射一个 AC 和实现/验证任务。
- 所有依赖编号存在、无环；READY 任务没有未解关键前提。
- 任务范围与设计接口一致；文件和命令区分现存、拟新增、未核实。
- 成功/失败结果能通过证据判定，不依赖开发模型自评。
- 历史问题、当前事实、目标设计和执行状态明确分开。
- 交接可从文档独立理解，不依赖本次聊天里的隐含背景。
