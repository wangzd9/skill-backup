# 飞书角色报告样式

普通问答、READY和进度均使用正常Markdown。事实范围、读取入口、通知时点与静默规则由[报告协议](../complex-task-coordinator/references/reporting-policy.md)维护；本Skill只负责呈现，不判断审核通过，不调用模型或发送消息。

## 通用呈现

群聊答复、cron final、定时与完成模型报告默认简体中文；必要模型名、路径、命令、标识和错误原文可保留。直接报告结论、证据/范围、阻塞和下一步，不发送英文工作草稿、逐条自问自答或未完成的核查过程作为最终汇报。

- 首行写实际角色、报告类型与生成时间，使用加粗；时间为 `YYYY-MM-DD HH:MM +08:00`。重要进度的发生或观测时间与标题分开，不把生成时间当完成时间。
- 标题下可用一句加粗结论突出当前结果。各区使用加粗标题，空行后接单层短bullet，一条只说一件事；**每条正文都要把字段名、状态/结论、阻塞/风险和下一步等重点加粗**，避免整段平铺。已有粗体不重复嵌套，事实和原意保持不变。
- 报告bullet以一个可核事实为单位；个人报告每条不超过240字，超长证据改为短结论加事件ID/哈希引用。不得把日志、多个观察源原因码、全量用量字段或其他角色工作串成一段；必要的采集缺口仍保留，拆成短条目放入正确分区。
- 一条事实的条件说明可以用分号连接，不按分号数量丢弃整份有效总结；仍限制单条长度并保留独立事实分条。总结失败须区分未取得模型结果、JSON解析失败、具体分区校验失败和送达未知，精确原因保存到本次回执。
- 审查待办按账本task/attempt/candidate绑定核对；当前`RESULT_READY`才称待裁决，`INCOMPLETE`须说明尚缺完整结果及协调者处置责任。被替换/取消候选的INCOMPLETE只列历史遗留数量与证据引用，不当当前待办、不自动关闭；旧候选或跨需求SUBMITTED/UNKNOWN仍显示并保留全局串行围栏。风险与下一步不得漏当前补验异常及owner。角色已切换work时，前单checkpoint只列原时点/事件引用，不回放成当前进展。
- 七区不能只有任务编号和阶段；需说明已有交付内容、固定版本的验证结果、返修问题ID及影响和实际接续条件。只读查询的`artifacts.manifest → report_context`提供同水位业务内容；展开前核哈希。开发者交付说明不冒充独立验收通过，旧检查点保留原时间与事件引用。
- 以报告契约中的具体功能和已证实结果组织内容；正文说明当前做到哪、尚缺什么和下一步。工程状态、代码位置、完整身份及日志按需查看证据，不能为简化表达删掉真实门禁或不确定性。
- 群聊发起回合默认只读，可查进度和答疑；“继续”“帮我修”不自动变成业务动作或待办。需动作时说明当前只读，并告知`全部权限：<具体动作>`的明确授权格式；不默认发起批准问句。群全权仅本回合；普通业务动作仍须角色租约，唯专用可信需求选择控制请求可独立排队。下一普通消息恢复只读；cron按已接受需求的持久范围及原门禁继续。
- 人工进度以专用只读工具`role_live_progress`的当次核验和有效回执为依据，逐角色说清本次核验结果、最近业务checkpoint原时间、具体缺口或冲突；无法确认标待核实。文档读取时间、owner存活和worktree改动不冒充新增业务进展；不机械照抄缓存sections，也不用“非生产实时探测”一句代替核查。生产任务只引用已有只读观察器结果，未配置、失联或采集陈旧具体说明。只读工具失败时仍保留完整分区，用可用事实生成结构化答复；只把受影响事实标为待核实，不回显内部错误码、预算/字节数或原始日志。用户直接询问工具故障时，再简短说明已核实原因与影响。
- 固定角色池报告写清当前已选需求；存在切换请求时区分“已接收、等待安全点”和“已生效”，给出阻塞角色/操作及证据。未选需求时说明待选；索引页不复制任务状态。全权只授当前人工回合，已接受需求的后台范围持续有效；不把正常cron说成等待用户逐轮授全权。
- 当前状态与已完成成果分开，已交付、已验证、已接受、已合入、已上线分别说明。跨项目角色只按当前显式订阅展示并标明项目，来源缺失/冲突显示待核实，不拿旧绑定补齐。一个角色只组织一组进度，其他在途或等待任务写在该角色内，不当作另一名执行者或第二项同时开发。
- 非进度的单一问题直接回答，不强行生成完整进度报告。不使用表格、多层列表、大段日志或HTML承载群内进度。

## 协调者：人工进度与正式巡检七区

用户在协调者会话里询问当前进度或要求汇报进展时，必须完整使用下面七区，不因工具错误、无新增或材料较长改成局部“关键路径/环境/待拍板”摘要，也不自行删区。每区都用加粗标题和单层短bullet；没有可核事实时保留该区并写明待核实原因。A/B/C及测试者名字后标当次核实状态，状态统一为空闲、工作中、等待、阻塞、暂停、待核实。重点字段与结论按通用规则加粗。

白天20分钟 `STATUS_BRIEF` 是专用机械状态短报，仍只列`执行者A（空闲）`、`执行者B（工作中）`、`执行者C（阻塞）`、`测试者（等待）`等当次核实状态；无需七区、进度百分比、用量或下一步长段。它不是用户在协调者会话里主动问进度的答复格式。空闲表示可领新任务；等待审查且已释放槽可空闲，不抹去后台责任。

人工问进度、自动poll的有意义事件和08:00汇总保持以下顺序；没有新增事实的区也保留准确简短状态，不用省略分区代替核实。无变化poll是否静默由报告协议决定。

自动协调者poll的最终输出必须是互斥的两种形式：**没有新业务事实且没有可执行协调动作时，只输出`[SILENT]`这一个ASCII标记；有需要报告的变化时，只输出简体中文七区报告。** 内部英文工作笔记、checkpoint摘要、轮次分析和“无动作”解释不得进入最终正文；不得先写正文再附`[SILENT]`。状态计算与检查点仍按原工具和业务流程记录，报告样式规则不改变事实、门禁或接续动作。

1. `**整体目标与进度**`：本期目标、已可使用或已验收部分、仍缺什么；无可靠总量不编百分比。
2. `**执行者进度**`：A/B/C名字后均加（空闲）/（工作中）/（等待）/（阻塞）/（暂停）/（待核实），再列各自的当前功能、已完成成果、仍在等待的条件及下一动作；各角色仅一组，不混淆当前执行与其他在途责任。
3. `**测试者进度**`：测试者名字后加同样状态，列正在验证什么、记录版本与已证明行为、尚未执行的验证及接续条件。
4. `**OCR情况和后续计划**`：当前运行、待裁决、失败或排队及其影响，后续顺序和启动条件。
5. `**强审查情况**`：需要与否、授权与调用情况、当前结果和接续；完整用量详情按需展开。
6. `**风险**`：本阶段当前有效的风险、影响、责任角色和解除条件；缺失或冲突说明具体问题。
7. `**下一步计划**`：按先后列近期动作、责任角色和实际前置条件，需要用户决定的明确指出。

08:00汇总保留七区，各角色条目可列业务时间段、成果、当前工作和必要依赖；客户端响应、任务排队、确认空闲及本地/云端调用次数、比例、实际token与有证据的费用只统计协调者本人，不汇总执行者/测试者用量。独立OCR/Codex强审用量不混入角色用量；采集缺口、未知路由/费用与usage覆盖率简短说明，完整明细附证据。

## 执行者和测试者：只报告自身四区

进度按以下四区组织，不复述其他角色的完整进度或全局审查账本。标题、字段名、结论、状态、阻塞和下一步均加粗重点：

1. `**当前工作**`：本人任务和实际阶段；当前没有执行时说明正在等待什么。
2. `**本次完成**`：本人新增成果与验证范围；没有新增如实说明，不能把别人的操作算成本人完成。
3. `**阻塞与依赖**`：只列直接影响本人接续的条件、责任角色和已有状态。
4. `**下一步计划**`：本人可执行动作，以及必须等待的真实前提。

本人名字也附（空闲）/（工作中）/（等待）/（阻塞）/（暂停）/（待核实）。领取成功由outbox脚本一句说明任务和开始工作，不强制四区；完成由原生模型总结。时段总结先用脚本事实再由短只读模型整理，仍只写本人，在四区内补工作时间段、LLM响应、任务排队、确认空闲及本地/云端调用次数/比例/token/可得费用和具体采集缺口。非进度的单一问题正常直答。
