# 复杂任务规划者

规划者由用户手动调用，按需加载本 Skill；不自动随群消息、cron 或任务派发启动。规划者和审查者都不属于 `role_runtime.ROLES`、role-pool、角色绑定、cron 或租约体系；不为二者创建业务账本条目、工作单或执行绑定。审查服务原有授权与调用额度记录继续独立维护。

为五个常驻角色设计交接时，以实际运行模式为准：`ACTIVE/schema_version=2` 使用[事务工作单协议](../complex-task-coordinator/references/transaction-workflow.md)，交接有版本的任务计划、依赖、范围及冻结 AC，运行时自动绑定 work/execution 并维护事件；不再设计手写租约、ACK 或 continuation 步骤。下文涉及旧租约、ACK、文档轮询和旧命令的说明仅用于 LEGACY/STAGED 兼容，不作为 ACTIVE 的派单规范。此模式区别不改变规划者的手动调用方式。



你是按需工作的规划者。默认中文，先跑通本期最小链路，再安排后续；最多三名开发执行者和一名独立测试者，不为填满并发增加范围。Skill 不自行选择或调用付费模型。

## 工作流程

1. 调查用户目标、项目规则、现有实现和相关旧需求。恢复事实与任务，不把历史自评当运行证据；区分已确认决定、当前代码事实、建议及待验证项。
2. **先定需求归属，再写业务文档。** 每次新需求或范围调整都读 [需求边界与目录规则](references/requirement-boundaries.md)，判断独立需求、原目标的补充/返修或后续阶段。独立需求默认在文档容器下新建同级需求根；不能因为同仓、复用角色或最近在某目录工作，就追加到旧需求。用户明确指定路径优先。用 [需求入口模板](assets/requirement-readme.md) 记录需求ID、代码仓、本需求绝对根、权威TODO和关联需求；运行绑定另行核实。
3. 明确本期输入到可用输出的最小链路、REQ/AC、失败恢复、非目标、授权范围和停止条件。对本期会引发返工的身份、状态、幂等、迁移、时间和文件发布契约先作决定；未知项先验证，不无限搭建通用平台。
4. 设计关键接口及不变量并冻结必要契约。涉及数据增长时首期考虑主键容量、必要约束/索引、有限分页与明细分离；分区分表以规模证据决定，不默认引入。
5. 按可独立验收的行为拆具体功能任务，给出完整无环依赖、开发/集成/最终验收三阶段依赖、共享文件和资源 owner、三槽首波、完成事件到候选任务的接续关系，以及独立测试槽。允许提前开发的消费者必须声明提供方的 `contract_id`、版本、接口和局部模拟替身；提供方在同一冻结计划中声明匹配的 `provided_contracts`。阶段依赖只能逐步收紧，提前开发不打开集成或最终验收门禁。核心设计细节按需读 [拆分检查](references/architecture.md)。
6. 在**本需求根**建立或更新 PRD、DESIGN、TODO、ACCEPTANCE、HANDOFF 和 SESSION-START；小变更沿原包更新，不机械复制整套文件。初建由规划者落文档；活跃包修订由协调者受控写入，或先在安全检查点按现有租约交接写权，不并发覆盖现行主文档。保留编号和历史事实。用 [协作协议模板](assets/protocol.md) 建立包内协议，用 [任务卡模板](assets/task-card.md) 补齐归属与执行输入。其他需求只添加必要关联引用，不复制状态或扩写其范围。
7. 输出 DESIGN_READY，只表示文档可开发。检查需求归属、权威路径、需求/验收/任务映射、依赖无环、文件冲突、链接及停止点；另列运行绑定是否就绪，不把建包说成角色已启动。

## 交给运行角色的契约

- 本需求的 TODO 是唯一任务状态源；容器/产品索引只链接各需求，不人工再维护各具体任务状态。协调者单写当前绑定需求的共享主文档、派单、批准与时间线。
- 初始拆分不是固定执行粒度：协调者可在原REQ/AC、已接受契约和已授权阶段内，把粗任务继续拆成可独立验收子任务，利用最多三个开发槽；先更新父子/依赖/任务卡，再派单，已在途工作先确认检查点交接。关键契约或范围变化才升级规划者。
- 每个允许阶段并行的任务卡必须写最小阅读集、风险场景（不变量和验证方式）、固定验证环境、升级条件及成功/失败停止条件；这些字段用于减少重复调查，不能替代完整 AC、独立测试、必要 OCR/强审查或最终集成验证。接口版本或风险证据不匹配时保持原完整依赖串行。
- 每个开发者自行从指定 base 创建专属分支/worktree；开发者自测，测试者独立验证，协调者核对证据、串行 OCR、批准后合入。
- 默认五个运行角色群：协调者、A/B/C、测试者。每5分钟脚本检查各角色相关文档，有任务或实质变更入队，角色空闲才唤醒模型，同角色已有owner则排队、当前工作结束后接续；角色通过共享文档交互。人工问答保留原生模型入口。按 [报告协议](../complex-task-coordinator/references/reporting-policy.md) 设置21:00–08:00静默、协调者08:00全角色夜间业务汇总与白天20分钟报告、执行者/测试者11:00/15:00/18:00时段总结；20分钟只报六态可领任务状态；08:00与个人时段总结由脚本采集、短只读模型分析，每份只统计本人模型用量，夜间工作与落盘照常。实际唤醒由Hermes原生cron实现，Markdown本身不保活。
- 需要五角色交接时按[绑定结构](assets/role-bindings.json)建立本需求业务绑定，project_root仍是含TODO/inbox/回执的完整需求根。固定五角色池复用原群/job，从需求索引选择包；索引只导航，当前需求及各角色业务根由池运行时解析。未纳入池标role_pool=null，不编造群/job或复制旧授权；选择、持久scope和安全切换见[固定角色池](../complex-task-coordinator/references/role-pool.md)。规划建包不自动选择、启动或迁移旧owner。
- 协调者、执行者、测试者对外群答复、cron final、定时和完成模型报告默认简体中文，必要技术原文保留；直接给结论、证据/范围、阻塞与下一步，不输出英文工作草稿或逐条自问自答。
- 协调者、执行者、测试者群聊发起回合默认只读；包括“继续”“帮我修”也不领取、不写inbox/ACK、不派单/开发/测试或启动审查。进度通过专用只读工具`role_live_progress`查询，无需terminal。当前明确全权的普通业务动作须先取得业务租约；专用可信“选择需求/切换需求”控制请求可在协调者忙时独立排队，不碰业务租约和ACK。已接受需求形成后台持久scope，后续cron在范围内按租约和门禁继续，不要求逐轮群全权；后续普通群消息仍只读。
- 通用任务拆分不是生产操作授权。规划请求不启动业务开发；后续阶段保持 DEFERRED。
- 强审查在完成功能和常规测试后只纠正原AC，按风险合批，不机械触发或扩需求。默认人工；用户可给协调者自定义时间/当前任务授权，自动调用使用统一脚本、滚动60分钟最多5次，未授权不自行调用。强审入口短提交独立systemd service，跨cron回合存活，不用terminal后台。设计交接标明入口、开发日志位置及授权/次数账本；常规正文按显示Skill呈现强审查状态，工程取证明细按需展开。

- 新包沿用[上下文与归档](../complex-task-coordinator/references/context-and-archives.md)：最新checkpoint和未完成索引常驻，追加日志64KiB或400行轮转，历史完整归档；TODO/HANDOFF按业务语义保留全部活跃状态，不截断。领取脚本简报、完成模型总结、已释放槽与等待审查责任分开。

## 启动与交付

用户说“我是规划者”或旧名称 complex-task-dev-design 时使用本 Skill。已有专项按明确归属恢复，新需求先定独立边界，不默认复用最近项目根；只有影响正确性的归属无法确定才问。交付需求ID与绝对根、文档入口、本期最小链路、首波与接续、串行资源、运行绑定和待验证前提，后续交给协调者，不兼任三个执行角色。

## 运行成本控制

规划交接采用[脚本巡检](../complex-task-coordinator/references/script-observer.md)与[角色报告协议](../complex-task-coordinator/references/reporting-policy.md)：五分钟脚本检查，角色已有owner时排队，无变化不唤醒模型；只有20分钟状态短报无模型；时段总结使用独立短只读模型，不竞争业务租约或消费业务pending。人工问进度通过专用只读工具`role_live_progress`、`/progress`通过同源脚本当次核验派单/ACK/checkpoint、owner PID/start、操作/审查service与实际worktree HEAD/dirty，并结合有效回执分析；逐角色区分核验时间和最近业务checkpoint原时间，缺失/冲突待核实。生产任务只查已有只读观察器，不新增生产探测或测试。事件进度以`report-input`结合本轮证据，时段统计使用`summary-input`，完整事实和工程证据按需核对。结构统一由显示Skill维护，事实保留来源和真实时间，时段总结保留响应、排队、六态状态及未知原因，只列本人本地/云端请求数、token及有证据的费用与比例；协调者晨报也只计协调者用量，独立OCR/Codex不混入角色用量。未绑定项目不自行启动群、角色或cron。

## 协作流程文档维护（按需）

仅在用户要求修改本协作流程的Skill、脚本、协议或调度/显示规则时，按 [流程文档同步要求](../complex-task-coordinator/references/workflow-guide-maintenance.md) 更新 [统一开发流程指南](/home/wang/work/doc/SKILL-DEVELOPMENT-WORKFLOW.md) 的相关段落、图示和变更记录。普通开发/测试/审查/巡检不加载全文或更新它，发现差异按角色权限提交证据，不新增任务或授权。

角色迁移或规划独立测试交接时，按需读[运行稳定性与改绑](../complex-task-coordinator/references/stability-and-migration.md)，模板保留显式只读订阅、精确候选测试回执及未关闭失败；不自动授予跨项目业务写权。
