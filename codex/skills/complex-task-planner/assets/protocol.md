# 五角色文档协作协议 v2.1

规划者把本模板落入本需求根的 inbox/PROTOCOL.md，填入需求ID、唯一绝对根、角色绑定、主分支、授权和现有工具调用方式。已有任务/回执保持兼容，不重置业务状态。

## 需求归属

本协议只管启动入口指定的需求包；代码仓、产品目录与本需求根分别记录。独立新目标由规划者判定归属，默认新建同级包；原REQ/AC返修留本包，不因同仓或复用角色把关联需求加入本期范围。跨包依赖引用需求/任务ID、固定产物和接受证据；各包TODO保持唯一状态源，产品索引不抄各具体任务状态。

当前工具读取project_root下的TODO/inbox/回执，该根必须是完整需求包。文档建包不自动创建群/cron；复用角色需先在安全检查点核对注册表、cron根与session入口，不把同一群/角色重复绑定多个根当成已支持并行。目录迁移不在普通巡检中自动执行。

## 单一来源与角色

- 本需求TODO：唯一业务任务状态与依赖源。DESIGN：契约。HANDOFF：最新恢复检查点。TIMELINE：事件历史，不替代状态。
- ROLE-BINDINGS.json：项目根、角色/群/Skill、cron、控制模式和迁移信息，不复制任务状态。
- 新包规划由规划者初始化；进入运行后协调者单写共享主文档、派单、decision、OCR批次、强审查包和全局时间线。活跃包规划修订先交协调者受控写入，或在安全检查点按既有租约交接写权；群聊与定时具有同一批准/调度权限。
- 协调者维护绑定的development_log：在重要交付、验证、审查、合入、阻塞变化及里程碑时按证据更新，不为无变化巡检刷日志。正式功能日志按仓库既有流程：功能完成并验证后及时生成/合并pending候选；用户明确批准后approved，实际发布成功后released并更新公开日志，不自行批准/发布。
- A/B/C 只写自己的代码范围、sessions、ACK、receipts、events；测试者只写指定测试材料、sessions/TESTER、test-receipts、验证报告与自身 events。
- 每个执行者自己新建任务专属分支/worktree；测试者独立取证；协调者审核门禁后合入，不代业务开发和日常测试。

## 领取、交付和接续

派单必须包含 task/attempt、固定 base、角色、范围、AC、停止条件和路径。先独立 ACK 后执行；已有派单允许只改 status ACK 的保留兼容，正文不改。扫描全部 inbox 中有效派单，不依赖自由文件名是否符合某个 glob。

任务状态沿用已有 TODO；常用交付状态 REVIEW_PENDING / TEST_REPORT_PENDING 只是等待审核，非通过。最新有效 attempt 由协调者明确，不能用新的无效文件覆盖已接受身份。接受后记录真实 merge 和合入后必要验证，满足门禁才 DONE。

依赖接受、阻塞解除、冻结交付释放槽后重新计算候选。本期已授权、依赖齐全、输入完整、文件/资源无冲突且 owner 确认可接才派。最多三路开发，不等整波；无可派任务不扩需求。强审查等待只冻结受审门禁。

协调者每轮巡检检查空闲开发槽；若任务过粗，在原REQ/AC、已接受契约和已授权阶段内主动拆分可独立验收的剩余工作。按实际可接人数分配，不按人数机械切分；共享文件、迁移链、资源和硬依赖仍串行。先更新TODO父子关系、子任务卡、依赖/接续、HANDOFF和拆分事件，再派单；总任务汇总各功能并完成集成验收，不重复派完整实现，子任务接受且必要集成验证完成才收口父任务。已ACK/在途工作先确认执行者检查点与交接边界，不能直接换owner重派；范围/关键契约变化升级。具体操作读协调者Skill的references/task-decomposition.md。拆分不增加逐任务强审；无可并行工作时说明具体串行原因和解除条件。

## 单写与恢复

绑定中的 runtime_script 提供 claim/renew/release、短控制 run、preflight、event 和 timeline。使用真实 Hermes 会话身份作 owner；能够定位独立会话 worker 时记录其 PID，不使用即将结束的 shell PID或共享 gateway PID。未知 owner 存活时不能自动抢占。

每个角色写入或执行关键控制动作前 claim；拿不到租约只核查和报告。用带 token 的 run 包裹短文档/派单/ACK/合入操作，确保与群会话互斥；run 内执行前重读相关版本，旧 token 不可复用。每轮控制动作结束立即 release；长测试/OCR/开发先写实际进程与固定快照检查点，释放控制租约，后续巡检只核查，不重复启动。

租约到期不证明 owner 已退出；PID/start identity 已失效时才可在到期后接管。无法定位 owner 时报告需要核对，禁止删除稳定锁 inode。协调者沿用 inbox/coordinator.lock，OCR 独立沿用 inbox/ocr.lock；文件存在不等于锁被持有。

同一owner的匹配token在未被接管时可以renew或release过期租约，之后才继续控制动作。未知owner中断后，先核实原会话与进程已停止并保存证据；用recover --owner 原owner --confirmed-stopped --evidence 证据绝对路径清理过期租约，再claim。recover拒绝仍存活PID和未到期租约，禁止自动用“超时”代替停止证明。

claim成功只代表取得文档写权限，不是重新启动业务或测试许可；同task/attempt/被测commit仍有存活或未核验进程时，只检查并续写状态，不再次ACK、测试或启动OCR。

运行示例（按绑定中的真实绝对脚本路径替换 RUNTIME 与 ROOT，TOKEN 为 claim 返回值，不在群公开）：

```text
python3 RUNTIME claim --project ROOT --role A --owner 本轮会话ID
python3 RUNTIME run --project ROOT --role A --token TOKEN -- 允许的短文档写入命令
python3 RUNTIME event --project ROOT --role A --token TOKEN --event-id 稳定事件ID --task TASK-xx --attempt 1 --status REVIEW_PENDING --summary 交付行为 --evidence 回执路径或commit --next 等协调者审核
python3 RUNTIME release --project ROOT --role A --token TOKEN
```

preflight 在每个巡检回合更新真实检查时间并报告 ACTIVE/PAUSED、旧 owner/租约情况。不要把重启/压缩理解成重新派已 ACK 的任务。异常中断保留日志、PID和资源身份，逾期告警，不自动 kill、reset 或重派。

## 5分钟巡检、分时段总结和事件

五个运行角色各有 poll/report 两个 Hermes 原生 cron，均显式绑定对应 Skill，origin 与 deliver 指向同一角色群。巡检不用Hermes monitor跳过检查本身：每5分钟由脚本真正核查，无变化不调用模型；独立检查、变化入队与原生角色接续按下方最新规则。

当前报告策略quiet-digest-v2（Asia/Shanghai）：21:00–08:00所有运行角色停止主动定时/事件群通知，但开发、5分钟脚本检查、必要模型接续、派单、测试、OCR和文档记录继续。协调者08:00汇总21:00–08:00全部角色时间段/任务、确认空闲、完成记录和当前工作，另附18:00–21:00补充；白天08:20–20:40保留20分钟全局短报。执行者A/B/C、测试者仅在11:00、15:00、18:00生成08–11/11–15/15–18时段总结（无任务也总结），取消旧20分钟及2小时空闲报告。所有总结no_agent，不新增模型汇报定时请求；白天实质变化落唯一事件后即时通报一次，夜间只落盘，用户主动提问可正常答复。时段总结分别呈现角色阶段、LLM客户端响应时间、任务排队、真实空闲；客户端API耗时不能称纯服务端排队，未知附具体原因与补采动作。时间为任务状态观察估算，等待/阻塞/未知不算空闲，不能倒填无证据历史。完整规则：/home/wang/.codex/skills/complex-task-coordinator/references/reporting-policy.md。未绑定专项仅同步模板，不新建cron。

有意义的派单、领取、返修、实质进展、阻塞/解除、交付、测试/OCR结论、批准、合入及暂停/恢复先落有权写的文档与唯一事件；白天可在本角色群一次通报。正常续租、重复等待和自身巡检记账不作为新进展。cron final 自动投递，禁止再 send_message 双发；角色事件唯一 event_id，协调者去重汇总 TIMELINE。

事件落盘后由同一五分钟检查/poll接续，已运行目标不重启。只有原生提前唤醒入口不会启用已暂停job时才使用；当前trigger_job会重新启用job，不用它绕过暂停。定时回合不创建或更改定时任务；巡检回合只有用户有效授权且明确需要时才通过统一限额脚本调用Codex，二十分钟报告仍只读不起跑。

用户可见进度统一读取本角色报告契约，再按 `feishu-progress-style` 呈现。协调者所有进度入口保留完整七区；执行者/测试者仅本人工作、成果、阻塞依赖及下一步。事实范围、时点及静默遵循complex-task-coordinator/references/reporting-policy.md，工程证据按需核对；报告不决定门禁或修改任务事实。

无变化、正常心跳、纯等待、自写回声与重复进展不主动群报，poll final仅[SILENT]；有意义的新完成、交付、失败、阻塞变化、返修、实质发现或待决策事项先落唯一事件，白天允许一条即时通报。人工询问正常答复。周期报告不是重复事件，不伪造时间线业务进展。实际排队延迟如实记录，5 分钟是调度周期而非模型运行时限。

## 审查和合入

弱模型 OCR 流程保留，由协调者串行触发；覆盖清单、大文件完整职责拆批、上下游契约、固定快照及在途运行全部记录。超时、空输出、缺工具不是通过；先确认旧批停止才重启。开发者与测试者都不跑 OCR。

强审查额外，默认人工触发；用户可授权协调者在自行指定的时长、起止时间或当前任务范围内自动调用Codex审查者。范围、原话/消息来源和绝对时间落盘到统一授权账本，无授权/过期/撤销仍等待人工；更换授权不重置额度。所有项目共用strong_review.py，滚动60分钟最多5次且在途串行，失败/超时/复审计入，禁止裸Codex/API绕过。协调者报告必含强审查分区，写当前需要与否、执行/返回状态、结论和后续；授权或额度影响接续时说明具体条件。完整授权、次数、在途与真实用量保留在原账本/详情，不在正文倾倒字段。默认在功能批次完成开发和常规测试后审，不增加实现前审查或按任务/commit机械触发；冻结原AC，具体风险、问题与门禁明确才REVIEW_NOW，旧PASS不覆盖新行为。

强审查只纠正原功能：CORRECTION须证明违反既定需求/AC，回派原任务最小修复；VERIFICATION_GAP只补证明原AC所需证据；OUT_OF_SCOPE（新功能、未来规模、偏好重构或额外质量标准）默认不派单、不进当前TODO、不阻塞。跨模块阅读须与当前错误有因果关系；真实样本和生产等独立阶段的原门禁不提前变成无关模块条件。复审只看问题ID、修复diff和必要上下文；问题关闭且原AC满足即收口，不以“还可完善”继续加单。同根因两轮未解决按原规则升级，不无限返修。历史已确认问题不因本次范围收紧自动撤销，现有待办按上述分类继续核对。

合入前核对代码、开发自测、必要独立验证、OCR及适用强门禁。禁止自动“先合后审”例外。同根因两轮返修失败升级；不得删测试、弱化断言或成功标准。已批准工程闭环与生产启用分别记录。

## 授权与结束

当前授权写在项目 HANDOFF；Skill 不新增推送、生产部署、NAS/处理机写入或付费调用授权。已有用户明确授权继续执行，不逐项重复询问。

PAUSED/CANCELLED/COMPLETE 时停止新业务领取，保存检查点与恢复入口；协调者安排暂停本专项周期任务，并发送最后报告。定时任务不是无限模型调用，逻辑角色通过文档和持久调度恢复。

## 人工交互、共同执行权与工程helpers

人工自然语言保留Hermes原生模型会话，问答/进展/方向讨论不自动入业务队列、不等五分钟巡检；夜间用户主动问话可答复。明确业务动作才保存原生消息身份与原文，群或cron获得同一协调角色租约后复读任务/attempt、派单、ACK及处理证据，已处理不重做。空闲时群可直接协调；owner忙时保留待办并解释，不抢占或恢复暂停。旧队列证据保留，observer ack不能消费业务请求。具体工具见complex-task-coordinator/references/runtime-helpers.md。

显式/progress可生成无模型进度，自然语言仍由原生模型答复。报告先运行绑定的`runtime_tools.py report-input --project ROOT --role ROLE`并读取本角色材料，长操作后最终汇报前刷新一次。完整`progress-facts --project ROOT --json`仅按需取证，不默认注入执行者/测试者上下文。各事实保留来源和可信时间，缺失/冲突具体说明，TODO、测试回执、OCR裁决与授权各负其责；不通过正文转换推断当前状态。机械负载直接GET指标，环境/恢复/长操作复用现有helpers；测试、审查及生产门禁不变。未部署或未验证时，不仅凭模板声称实际生效。


## 确定性观察、记账和时间

固定长任务以现有task_observation脚本五分钟只读采样，正常观察与业务事件分离；安全session/event记账使用runtime_tools role-record，测试证据使用evidence-record/evidence-check。相同事件镜像去重、冲突保留核对，处理后重新核对输入再ACK。群报时间使用完整日期、HH:MM与时区，从系统或可信原始证据读取；内部自动记录的秒可保留，历史分钟记录保留原始精度，不补造秒。发生、观测、补录分开。未知发生时刻明确未记录，不用模糊钟点或文件mtime冒充发生时间。原测试/OCR/强审/授权/合入门禁保持。
