## 保留的边界

- 规划者仍手动调用；规划者和审查者仍是按需 Skill，未加入五角色、role-pool、绑定、cron、租约或业务账本。
- auto 需要云端时仍优先 `sub2api/deepseek-v4.1-flash`。
- 缺失历史原生行的 scope 继续 UNKNOWN；没有批量删除、伪造退出、自动 PASS、ACK 或清 owner。
- R1 存储优化仍保持 LEGACY_ONLY。活动检测没有经业务确定的阈值 / 可信等待期限时，继续明确 POLICY_UNCONFIGURED / UNVERIFIABLE；不杜撰等待超时或无活动。
- 供应商价格 / 可用性、压缩失败及具体项目 AC 失败不由观察器伪造修复；没有宣布生产提速或 token 节省。
- 源码已被新进程读取，不等于旧 gateway 完整采用。21:28 只读复核仍无生产 business.sqlite3 / tick 回执，且有原生 running 行；能力探测单独不构成采用。生产切换仍须安全收口全部 writer、最终库存对账、STAGED prepare 及 P0/T1/T2/M/R 同版本真实门集合。历史 M 为 UNVERIFIED，已用 2 次模型请求和唯一 1 条群总结；本轮无真实模型或群投递。

## 安装、发布、回退

cron 包装不能用越界链接：原生 `_resolve_script_path` 会拒绝。已补真实原生解析器和 `/usr/bin/python3 -I` 冷启动回归；lease_observe 的部署副本从本 profile 的已安装插件定位受管依赖。部署副本、canonical 源码和发布清单逐字节一致，不能靠手抄维持。

`python scripts/runtime_layout.py` 只核入口；加 `--apply` 安装 Skill 链接及 cron 受管部署副本，拒绝覆盖字节不同的普通文件。`deployment/systemd/role-document-observer.service` 提供 canonical 运行时入口；现有服务可沿兼容链接执行，不为源码提交重启 gateway 或结束活 worker。

`python execution_retention.py --home ... --pool ...` 默认只给可归档证据；`--apply` 才归档。未核身份不会因年龄超过默认七天而归档，原生 metadata / 原 scope 字节和收口证据一起保留。

`python scripts/build_release.py --output <全新私有归档> --validation <本版本验证.json>` 固定精确源码和两仓 commit；`--verify <归档>` 只读检查。发布包不含业务状态、凭据，也不凭打包授予迁移权。Skill 文档等配置源码以准确哈希随发布包保存。
