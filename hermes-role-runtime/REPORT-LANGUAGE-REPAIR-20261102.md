# 汇报改为日常中文

版本：0.17.16。日期：2026-11-02。

用户要求保留原有七区格式，同时让汇报能直接看懂。过去的规则只要求含中文，允许大量技术标识；只要带中文标签，内部状态和日志也能通过格式检查。程序回退又直接拼接任务编号、英文状态和旧交付说明，因此只改一句“请用中文”不能覆盖实际出口。

本次统一处理人工查询、后台巡检、定时总结、程序回退和汇报技能：

- 先说功能、已完成结果、缺什么、谁处理及下一步。保留七区/四区、角色中文状态、单层条目和重点加粗。
- 已知状态用中文解释；保留未执行、未通过、未知，以及开发、自测、独立测试、批准、合入、上线的区别。
- 技术细节留证据：任务编号只在确需区分时展示；不把事件号、工作单号、分支和原始错误堆在正文。必要产品名、命令、文件路径及协议名保持准确。
- 人工和后台报告即使分区正确，仍堆内部状态字段时，使用当次只读事实重新排版；不会因此执行新的业务动作。时段总结转换已知显示用词，证据引用和源输入保持原样。
- 回退报告明确显示已有独立测试结果，说明等待前置任务的原因；不再把开发者交付时的“等待测试”当当前状态。正常在跑的审查不写成代码缺陷。
- 需要用户决定只列真实待决问题。协调者职责内的事不凭空转成“待你拍板”；本次不修改授权、业务状态、通知时点或静默规则。

技能：`feishu-progress-style` 1.13.5、`complex-task-coordinator` 1.23.2。Hermes 配置使用这些外部技能目录。统一流程指南更新至 3.42，保留其他会话的分支收尾修改。
