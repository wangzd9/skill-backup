# 裁决、前置需求接续与通知闭环修复

版本：0.17.15。日期：2026-11-02，Asia/Shanghai（+08:00）。

## 现场根因

1. `RUN_SELECTED` 事件 **16103，2026-10-31 21:46:48 +08:00** 将需求从 Foundation 切到 Spray。`BusinessLedger._select` 自动把原 ACTIVE run 设为 DRAINING；这不是用户暂停，也没有“DRAINING 必须用户三选一审批”的合同。原生执行仅支持当前 run，旧协调工作被安全释放；前置任务尚未完成却没有返回调度链。
2. 原生 `answer_source` 只认识字母、按解读/方案等窄形式，不认识真实消息“两个都批”。因此 ingress 没有登记，群模型随后调用受控入口也不能补造原生来源。后台从未获得这条持久输入，等待下一 tick 不会自行修复。
3. 工作输入与决策目录按当前 run 过滤；旧需求的审查责任、用户答复与下游冻结依赖无法组成可执行接续。检查点反复复制“等用户”，把内部接续问题升级成不存在的人工审批。
4. `waiting_external` 和 `next` 只是文本，不产生正式用户问题或 outbox。夜间 notify 被 SUPPRESSED 后也没有未决问题的白天重建。口头说“升级上报”没有送达证明。
5. 汇报的 `progress_context` 只取首段，B 的首段恰好是标题；`_live_bullet` 又按 205 字符截断，直接切坏 DEP 等关键条件。该现象发生在本地渲染，不能归因于飞书或模型输出上限。

## 完整接续路径

- **识别依赖：** 仅接受冻结 inputs 中的依赖声明与精确上游需求引用；上下游都必须有当前有效的已接受本地开发策略，且上游所有已规划任务均在原策略范围内。没有依赖或授权就不自动挑选其他需求。
- **安全调度：** 在原有 scheduler/sweep 事务中核所有 ACTIVE/DRAINING execution、writer 与外部 SUBMITTED/UNKNOWN；未知不视为结束。在安全点停放下游原 work ID、checkpoint、ACK 水位和工作树，再用原生选择切至上游。不复制身份，不在下游 scope 写上游。
- **准入收敛：** 接续目标成立后暂停空闲轮询重入，已运行 writer 正常保存退出，避免角色交错重入饿死安全点。未处理答复、未知服务/交付恢复与旧单安全退出保留；通知事件不作为新业务结果自唤醒。
- **自动返回：** 前置任务、适用需求最终验收与正式问答真正完成后，安全返回并恢复原工作单。前置叶任务已完成但最终验收未完仍纳入接续。人工暂停、取消、撤权及新的明确选择（包括重新选中同一前置需求）优先；保持原 scope、独立测试、OCR、审查、合入和真实环境边界。
- **裁决登记：** 原生短答复保留原文、消息身份、原时间与原问题证据。跨安全接续后仍列为协调者待办；`resolve_user_decision` 只记录语义关联，不替代真实批准、测试或合入。未处理答复不再被普通等待抑制。
- **真实人工问题：** 协调者通过 `checkpoint.user_questions=[{decision_id,question,options,reason}]` 留存问题和选项，走原 outbox。夜间未决事项白天继续提示；按稳定对象去重，未处理答复在 15 分钟及 1 小时分级提示。已解决或被替代的待投递通知明确抑制，UNKNOWN 仍禁止自动重放。
- **汇报：** 使用完整语句或明确证据引用，不按字符切断条件；交付说明跳过空标题并保持开发者记录性质。前置依赖、内部责任、用户答复和真正待用户问题分别显示。历史等待判断不冒充当前条件，七区与短条上限保持。
